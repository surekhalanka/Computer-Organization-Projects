📋 Project Overview

In this project, you'll analyze the complete CPU memory hierarchy (L1, L2, L3, Main Memory) and how data flows through multiple cache levels in response to memory accesses. You'll study prefetching strategies, cache coherence, and replacement policies across the hierarchy. The goal is to understand how modern multi-level caches balance speed, capacity, and power to hide memory latency in real-time workloads.

🎯 Real-World Scenario

TradeFlow Corp: Real-Time Stock Market Analytics

Background: TradeFlow operates a real-time stock market trading platform serving 100,000 concurrent traders. Each trader's workstation runs analytics on 5,000 stock symbols, performing 10,000+ memory accesses per second. The system must deliver price updates in < 1 millisecond latency (3,000 CPU cycles @ 3 GHz). Modern CPUs employ 3-4 levels of cache (L1/L2/L3/Main Memory) with decreasing speed and increasing capacity. Cache misses cascade through the hierarchy—missing L3 requires 200+ cycles to fetch from main memory, devastating latency-critical trading systems.

Performance Requirements:

  • Response Latency: < 1 ms = < 3,000 cycles @ 3 GHz
  • Memory Access Rate: 10,000+ accesses/sec per trader
  • Cache Hit Rates: L1 > 85%, L2 > 95%, L3 > 98%
  • Prefetch Accuracy: > 80% (useful prefetches)
  • Cache Coherence: < 50ns update latency across cores
  • Power Budget: All caches < 20W (memory system)
  • Working Set: ~1 MB stock data (index + prices + history)

⚙️ CPU Memory Hierarchy Architecture

The Cache Pyramid

CPU Core (Registers: 64 B, 0 cycles)
L1 Cache (32 KB per core)
Latency: 1-3 cycles | Bandwidth: 32 GB/s | Power: 1W
L2 Cache (256 KB per core, private)
Latency: 5-7 cycles | Bandwidth: 16 GB/s | Power: 2W
L3 Cache (8 MB shared)
Latency: 15-20 cycles | Bandwidth: 8 GB/s | Power: 5W
Main Memory (DDR4 16 GB)
Latency: 100-200 cycles | Bandwidth: 4 GB/s | Power: 10W

Inclusive vs Exclusive Hierarchy

Inclusive Hierarchy (Intel model)

Rule: Data in L1 is also in L2, and L2 data is also in L3

Advantage: Coherence easier to maintain, smaller tags needed

Disadvantage: Larger capacity needed (data duplication)

Example: Stock price at 0x1000 in L1 → must also be in L2 and L3

Exclusive Hierarchy (AMD model)

Rule: Data in L1 is NOT in L2 (only in L1 or L2, not both)

Advantage: Better capacity utilization (no duplication)

Disadvantage: More complex coherence, larger tags

Example: Stock price at 0x1000 in L1 evicts from L2 on L1 hit

Multi-Core Challenges: Cache Coherence

Problem: With 8+ cores, each with private L1/L2, how do we keep stock prices consistent?

MESI Protocol (Most Common)

  • Modified (M): Core has written data (only this core has valid copy)
  • Exclusive (E): Core has clean copy, no other core has it
  • Shared (S): Multiple cores have copy (read-only)
  • Invalid (I): Data is stale (another core modified it)

Example Trade Update:

Core 0 reads Apple stock: L1=S (Shared), L2=S, L3=S (all cores can read) Core 0 buys Apple: L1=M (Modified), broadcasts invalidation Core 1-7: L1=I, L2=I (apple stock invalid, must refetch) Core 1 reads Apple: L1=S (fetches from Core 0 or L3)

📊 Stock Market Trading Workload Characteristics

Test Case 1: Portfolio Rebalancing (Baseline)

Workload: Read 5,000 stock symbols sequentially (end-of-day rebalance)

Memory Pattern: Sequential index access, each symbol ~200 bytes

Working Set: ~1 MB (fits in L2)

Expected Hit Rates:

  • L1: 85% (register/stack miss some)
  • L2: 98% (working set resident)
  • L3: 99% (shared data available)

Test Case 2: Real-Time Price Updates (Hot Path)

Workload: Update 50 favorite stocks continuously (10x/sec)

Memory Pattern: Random access to hot ~10 KB data

Working Set: ~10 KB (fits in L1)

Expected Hit Rates:

  • L1: 95%+ (hot data resident)
  • L2: 99%+ (L1 misses caught)
  • L3: 100% (rarely needed)

Test Case 3: Multi-Core Coherence (Shared Data)

Workload: 8 traders accessing same symbols (market volatility)

Memory Pattern: Alternating reads and writes to shared index

Challenge: Cache invalidations, MESI state changes

Expected Hit Rates:

  • L1: 75% (invalidations on writes from other cores)
  • L2: 90% (misses due to coherence traffic)
  • L3: 95% (coherent shared state)

Test Case 4: Prefetch Effectiveness (Hardware vs Software)

Workload: Sequential scan with prefetcher on/off

Prefetch Strategy: L1 prefetch next 4 blocks, L2 prefetch L3, L3 prefetch main memory

Expected Hit Rates (with prefetch):

  • L1: 92% (prefetch hides misses)
  • L2: 99% (prefetch from L3)
  • L3: 99.5% (prefetch from memory)
