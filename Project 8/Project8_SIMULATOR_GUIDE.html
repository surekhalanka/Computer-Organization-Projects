📖 Core Concepts

1. Memory Hierarchy Levels

L1 Cache (Level 1)

  • Size: 32 KB typical (split 16 KB I-cache + 16 KB D-cache per core)
  • Latency: 1-3 cycles (fastest)
  • Bandwidth: 32 GB/s
  • Type: Private to each core
  • Hit Rate Target: 85-95%
  • Power: ~1 W

    • Purpose: Store most-frequently accessed data (hot data). If not hit here, CPU must wait (stalls).

L2 Cache (Level 2)

  • Size: 256 KB typical (per core, private)
  • Latency: 5-7 cycles
  • Bandwidth: 16 GB/s
  • Type: Private to each core
  • Hit Rate Target: 95-98%
  • Power: ~2 W

    • Purpose: Catch L1 misses (prevent stalls). Working set often fits here.

L3 Cache (Level 3)

  • Size: 8 MB typical (shared across all cores)
  • Latency: 15-20 cycles
  • Bandwidth: 8 GB/s
  • Type: Shared among all cores
  • Hit Rate Target: 95-99%
  • Power: ~5 W

    • Purpose: Large shared pool (allows all cores to benefit). Miss here → main memory (200+ cycles).

Main Memory (DDR4)

  • Size: 16+ GB
  • Latency: 100-200 cycles (slowest)
  • Bandwidth: 4 GB/s
  • Type: Shared system memory
  • Power: ~10 W

    • Purpose: Unlimited storage. Every cache miss here adds ~150 cycles stall.

2. Cache Hit/Miss Metrics

Hit Rate Formula

Hit Rate % = (Hits / Total Accesses) × 100

Example: If L1 has 8500 hits out of 10000 accesses
L1 Hit Rate = (8500 / 10000) × 100 = 85%

Miss Rate Formula

Miss Rate % = (Misses / Total Accesses) × 100
                = 100% - Hit Rate %

Example: L1 Miss Rate = 100% - 85% = 15%

3. Average Memory Access Time (AMAT)

AMAT Calculation

AMAT = (L1_HitRate × L1_Latency) 
       + (L1_MissRate × L2_Latency) × (L2_HitRate + L2_MissRate × L3_Factor)

Simplified 3-level:
AMAT = H₁×T₁ + M₁×(H₂×T₂ + M₂×(H₃×T₃ + M₃×T_mem))

Where:
  H₁ = L1 Hit Rate,  T₁ = L1 Latency (1-3 cycles)
  M₁ = L1 Miss Rate, H₂ = L2 Hit Rate among L1 misses
  T₂ = L2 Latency (5-7 cycles), etc.

AMAT Example Calculation

Given:
  L1: 85% hit rate, 2-cycle latency
  L2: 95% hit rate, 6-cycle latency
  L3: 98% hit rate, 18-cycle latency
  Memory: 150-cycle latency

AMAT = 0.85×2 + 0.15×(0.95×6 + 0.05×(0.98×18 + 0.02×150))
     = 1.7 + 0.15×(5.7 + 0.05×(17.64 + 3.0))
     = 1.7 + 0.15×(5.7 + 1.032)
     = 1.7 + 0.15×6.732
     = 1.7 + 1.01
     = 2.71 cycles per access

Interpretation: Avg access takes 2.71 cycles (excellent—most hit L1!)

4. Inclusive vs Exclusive Hierarchy

Inclusive Hierarchy (Intel)

L1 Cache: [Apple, Google, Microsoft, Tesla, Amazon, Meta, Nvidia, Visa] ↓ (contained in) L2 Cache: [Apple, Google, Microsoft, Tesla, Amazon, Meta, Nvidia, Visa, ... 32 more] ↓ (contained in) L3 Cache: [All L2 data + 128 more stock symbols]

Rule: If data is in L1, it's also in L2 and L3 (subset relationship).

Advantage: Simpler coherence (invalidate just one level), easier tag management.

Disadvantage: Wasteful capacity (duplication across levels).

Exclusive Hierarchy (AMD)

L1 Cache: [Apple, Google, Microsoft, Tesla, Amazon, Meta, Nvidia, Visa] ⊕ (exclusive) L2 Cache: [Tesla, Amazon, Meta, Nvidia, Visa, ... 48 more (NOT in L1)] ⊕ (exclusive) L3 Cache: [All symbols NOT in L1 or L2]

Rule: Data is in ONLY ONE level at a time (exclusive OR).

Advantage: Better capacity utilization (no duplication).

Disadvantage: More complex coherence, larger tags needed.

5. Prefetching Strategies

Hardware Prefetch (Automatic)

  • How: CPU detects sequential access pattern and prefetches next blocks automatically
  • L1 Prefetch: Fetch next 4 cache blocks (~256 bytes) into L1
  • L2 Prefetch: Fetch next block from L3 into L2
  • L3 Prefetch: Fetch next block from memory into L3
  • Example: CPU reads stock at 0x1000 → prefetches 0x1040, 0x1080, 0x10C0, 0x1100
  • Accuracy Goal: > 80% (minimize pollution)

Software Prefetch (Compiler)

  • How: Compiler inserts prefetch instructions into code
  • Example: PREFETCH [array[i+8]] loads ahead before use
  • Benefit: Hides latency for predictable patterns

Prefetch Metrics

  • Prefetch Accuracy: (Used Prefetches / Total Prefetches) × 100 | Target: > 80%
  • Prefetch Pollution: Unnecessary prefetches that evict useful data | Target: < 20%

6. Cache Coherence (MESI Protocol)

The Problem (Multi-Core)

With 8 cores, each with private L1/L2, how do we keep Apple stock price consistent?

Core 0: Apple = $150.00 (in L1) Core 1: Apple = $149.99 (in L1) ← Stale! (old value) Core 2: Apple = $150.50 (in L1) ← Wrong!

Solution: MESI coherence protocol ensures all cores see latest value.

MESI States

State Meaning Valid? Shared? Dirty?
Modified (M) Core has written data (dirty, only this core has it) ✓ No Yes
Exclusive (E) Core has clean copy, no other core has it ✓ No No
Shared (S) Multiple cores have clean copy (read-only) ✓ Yes No
Invalid (I) Data is stale (another core modified it) ✗ N/A N/A

State Transitions Example

Core 0 reads Apple: M(M)=S, others=S (all cores can read) Core 1 reads Apple: → now all in Shared state Core 0 buys Apple: M(M)=M, others=I (Core 0 exclusive, others invalid) Core 1 reads Apple: → requests from Core 0 or memory → gets latest $150.25 value

Coherence Traffic

  • Invalidation Messages: "Discard your copy of Apple" → sent by writer
  • Update Messages: "Apple is now $150.25" → sent to all cores
  • Cache-to-Cache Transfers: Core 0 sends modified block to Core 1 (faster than memory)
  • Target: < 1 GB/s coherence traffic (avoid saturation)

📊 Understanding the Simulator Output

Hit Rate Display

L1 Hit Rate: 85% → 85 out of 100 accesses found in L1

L2 Hit Rate: 98% → 98 out of 100 L1 misses found in L2

L3 Hit Rate: 99% → 99 out of 100 L2 misses found in L3

Combined: Only 0.15% (1 in 667) accesses go to main memory = fast system!

AMAT Interpretation

AMAT = 2.71 cycles: Average access takes 2.71 CPU cycles

  • 0.1-2 cycles: Excellent (hits mostly in L1)
  • 2-5 cycles: Very good (some L2 misses)
  • 5-10 cycles: Good (L3 misses starting to hurt)
  • >10 cycles: Poor (too many main memory accesses)

For trading system: need < 3,000 cycles total = < 3 µs latency. AMAT < 2.71 cycles = 0.9 µs (well within budget!)

Power Consumption Breakdown

Component Baseline Power Miss Penalty Power Notes
L1 Cache 1.0 W +0.001 W per miss Fast, low power
L2 Cache 2.0 W +0.002 W per miss Moderate power
L3 Cache 5.0 W +0.005 W per miss Shared, larger power
Coherence 0 W ~0.0001 W per message Buses, serializers

Total < 20W: TradeFlow system power budget met! (typical CPU ~65W + 15W memory.)

Coherence Metrics

Coherence Messages: Total invalidations + updates. Target < 1,500 (10% of accesses).

Invalidations: "Discard your copy" messages. Causes L1/L2 misses on next access.

C2C Transfers: Cache-to-cache transfers (faster than memory). Every message = 64 bytes @ 15 GB/s = 4 ns.

Coherence Traffic: Total bytes transferred. At > 1 GB/s, bus becomes bottleneck!

Prefetch Metrics

Prefetch Accuracy: (Useful Prefetches / Total Prefetches) × 100%. Target > 80%.

  • High accuracy (85-95%): Prefetcher is helping. Few wasted prefetches.
  • Low accuracy (<60%): Too many prefetch misses. Consider disabling (prefetch pollution).

Prefetch Pollution: % of prefetches that evict useful data. Keep < 20%.

💡 Tips & Troubleshooting

Achieving 95%+ L1 Hit Rate

  • Reduce working set size (code optimization, algorithm change)
  • Increase L1 size (32 KB to 64 KB)
  • Align data structures to cache lines (64-byte boundaries)
  • Prefetch hot data on startup

Reducing AMAT Below 3 Cycles

  • Keep L1 misses < 15% (target 85%+ hit rate)
  • Ensure L2 is large enough (2× working set minimum)
  • Enable hardware prefetch (10-20% AMAT improvement)
  • Optimize memory access patterns (sequential > random)

Minimizing Coherence Overhead

  • Partition data by thread (avoid false sharing)
  • Use locks/atomics sparingly (each write invalidates copies)
  • Use read-only replicas (Shared state in MESI)
  • Reduce core count sharing data (8 cores more coherence than 4)

Common Mistakes

  • Ignoring L2/L3 misses: L2 miss = 5-7 cycle penalty! Not to be overlooked.
  • Over-prefetching: Too many prefetches cause pollution, waste bus bandwidth.
  • Assuming Inclusive = better: Inclusive wastes capacity; exclusive more efficient (but complex).
  • Forgetting about coherence: Multi-core systems lose 10-20% performance to coherence traffic!

Real-World Optimization Example (TradeFlow)

Problem: Average latency 4 ms (too slow). Trading system target: 1 ms.

Solution Steps:

  1. Measure current AMAT (found: 8 cycles, 2.67 µs per access, OK).
  2. Check L2 hit rate (found: 90%, should be 95%+).
  3. Increase L2 from 256 KB to 512 KB → L2 hit rate jumps to 96%.
  4. AMAT improves to 5.2 cycles.
  5. Enable hardware prefetch → AMAT drops to 4.8 cycles.
  6. New end-to-end latency: ~1.5 ms (hit 1 ms target!) ✓
