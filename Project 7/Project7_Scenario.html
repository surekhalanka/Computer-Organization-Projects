📥 Project 7: Cache Block Size Effect

Scenario: Large File Download

📋 Project Overview

In this project, you'll analyze how CPU cache block size (also called cache line size) impacts performance on large sequential file downloads. You'll compare block sizes from 16 bytes to 256 bytes, measuring hit rates, miss penalties, memory bandwidth utilization, and bus traffic. The goal is to determine the optimal block size for download workloads—balancing spatial locality exploitation against memory bandwidth and cache line fill time.

🎯 Real-World Scenario

DataFlow Systems: Large File Download Optimization

Background: DataFlow Systems operates a cloud storage platform handling 10 million file downloads/day. Users download files ranging from 100 MB to 10 GB (videos, datasets, archives). Each download streams through CPU cache on its way to disk/network. The cache block size determines: (1) How many bytes fetched per memory access, (2) Prefetch effectiveness, (3) Memory bus utilization, (4) Wasted bandwidth on unused data.

Performance Constraints:

  • Download Throughput: > 1 GB/sec (10GbE network)
  • Cache Hit Rate: > 95% (prefetch should hide memory latency)
  • Memory Bus Utilization: > 80% (avoid wasted fills)
  • Cache Block Fill Time: < 20 cycles (must keep up with CPU)
  • Power Consumption: Minimize memory bus traffic (power scales with bandwidth)
  • Cache Pollution: Don't evict hot data with large unnecessary blocks
  • Prefetch Distance: 4-8 blocks ahead (hidden in latency)

⚙️ Cache Block Size Analysis Framework

Why Cache Block Size Matters

Key Insight: Block size determines spatial locality exploitation. Larger blocks fetch more data per miss (amortize miss penalty), but waste bandwidth if data unused. Smaller blocks reduce pollution but increase miss count.

Block Size Trade-offs

Block Size Typical Miss Penalty Bus Traffic/Miss Spatial Locality Cache Pollution Use Case
16 bytes ~20 cycles 128 bits Poor Minimal Cache-hostile workloads
32 bytes ~35 cycles 256 bits Moderate Low Pointer-heavy (linked lists)
64 bytes (Standard) ~60 cycles 512 bits Good Moderate General-purpose (Project 5-6)
128 bytes ~120 cycles 1024 bits Excellent Moderate-High Streaming, sequential
256 bytes ~240 cycles 2048 bits Outstanding High Large file transfers

Impact on Performance Metrics

Block Size Miss Rate Impact Hit Rate @ 32KB Memory BW @ Saturation Effective Latency
16 bytes High misses (small blocks) 70% 2 GB/s (light) ~30 cycles
32 bytes Moderate misses 80% 4 GB/s (medium) ~20 cycles
64 bytes Baseline (2-3 misses/1000) 88% 8 GB/s (standard) ~15 cycles
128 bytes Few misses (large blocks) 94% 12 GB/s (heavy) ~20 cycles
256 bytes Very few misses 97% 16+ GB/s (saturated) ~30 cycles

Miss Penalty vs Block Size

Key Relationship: Miss Penalty = Cache latency + Fill Time + Contention

Miss Penalty Components:

  • Tag lookup: ~2 cycles (constant)
  • Data fetch from memory: B/BW cycles (B = block size, BW = bus bandwidth)
  • Bus contention: 0-10 cycles (depends on other traffic)
  • Result delivery: ~1 cycle

Example (64-byte block @ 8GB/s bus):

Fetch time = 64 bytes / (8 GB/s) = 8 ns = ~24 cycles @ 3GHz Total miss penalty = 2 + 24 + 2 + 1 ≈ 29 cycles ≈ ~30 cycles typical

📊 Large File Download Workload Characteristics

Test Case 1: Sequential 100 MB File (Baseline)

Workload: Download file from start to end, sequential access

Memory Pattern: Address A, A+64, A+128, ... (strictly sequential)

Expected Hit Rates by Block Size:

  • 16 bytes: 75% (many misses)
  • 32 bytes: 82% (fewer misses)
  • 64 bytes: 90% (good spatial reuse)
  • 128 bytes: 96% (excellent prefetch)
  • 256 bytes: 98% (near-optimal)

Test Case 2: Random Seek Pattern (Database Scan)

Workload: Random seeks within file (index scans, B-tree traversal)

Memory Pattern: Address A₁, A₂, A₃, ... (scattered, 512 KB gaps)

Spatial Locality: Within each 4 KB page, some sequential access

Expected Hit Rates:

  • 16 bytes: 40% (no prefetch help)
  • 32 bytes: 45% (little gain)
  • 64 bytes: 52% (some intra-page help)
  • 128 bytes: 58% (more intra-page)
  • 256 bytes: 62% (over-fetching hurts)

Test Case 3: Streaming with Prefetch (Video Stream)

Workload: Video codec reads frame buffer sequentially, CPU prefetches

Memory Pattern: Sequential with 1-2 cache block lookahead

Expected Hit Rates:

  • 16 bytes: 80% (prefetch helps small blocks)
  • 32 bytes: 88%
  • 64 bytes: 95% (ideal for prefetch distance)
  • 128 bytes: 96% (over-prefetch)
  • 256 bytes: 94% (too aggressive)

Test Case 4: Mixed Workload (Real Download)

Workload: Mostly sequential with occasional index lookups

Memory Pattern: 90% sequential, 10% scattered

Expected Hit Rates:

  • 16 bytes: 68%
  • 32 bytes: 75%
  • 64 bytes: 85%
  • 128 bytes: 90%
  • 256 bytes: 92%
