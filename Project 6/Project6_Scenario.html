📹 Project 6: Cache Size Impact

Scenario: Video Streaming Caching

📋 Project Overview

In this project, you'll analyze how CPU cache size impacts performance on video streaming workloads. You'll compare cache configurations ranging from 4 KB to 256 KB, measuring hit rates, access times, and buffer stalls. The goal is to determine the optimal cache size for streaming systems—balancing performance gains against area and power constraints.

🎯 Real-World Scenario

StreamVision Inc: Video Delivery Platform Optimization

Background: StreamVision operates a global video streaming platform serving 50 million concurrent users watching 4K video. Each stream requires real-time CPU cache lookups for: video frame buffers, codec state machines, network packet queues, and playback metadata. Cache misses cause frame buffering (stalls), reducing video quality. StreamVision must choose the optimal cache size for their next-generation edge server CPU.

Performance Constraints:

  • Streaming Quality: 4K @ 60fps requires < 2ms per frame = < 6,000 CPU cycles @ 3GHz
  • Buffer Stall Limit: < 2% of frames stall (causes visible buffering)
  • Cache Hit Rate: > 97% (video workload is highly predictable)
  • Die Area Budget: Cache < 80mm² (cost limit)
  • Power Envelope: < 15W for L1+L2 cache @ 3GHz
  • Concurrent Streams: 32-128 streams per server (working set 1-10 MB)
  • Frame Buffer Size: ~10 MB (4 frames × 2.5 MB per 4K frame)

⚙️ Cache Size Analysis Framework

Why Cache Size Matters for Video

Key Insight: Video has high temporal and spatial locality—same buffers accessed repeatedly. Increasing cache size captures more of working set, reducing misses exponentially until diminishing returns.

Cache Size Configurations:

📊 Video Streaming Workload Characteristics

Test Case 1: Single 4K Stream (Baseline)

Workload: One video stream, 2.5 MB frame buffer, 10 KB codec state, repeated access pattern

Memory References: ~5,000 per second = ~1,667 per frame @ 3fps

Expected Hit Rates:

  • 8 KB: 70% (buffer misses)
  • 16 KB: 82% (some buffer fit)
  • 32 KB: 90% (most working set fits)
  • 64 KB+: 95%+ (all buffer resident)

Test Case 2: Multiple Streams (16 concurrent)

Workload: 16 independent 4K video streams interleaved

Working Set: 16 × 2.5 MB buffers = 40 MB data

Key Challenge: Capacity misses dominate; associativity helps less

Expected Hit Rates:

  • 8 KB: 25% (severe thrashing)
  • 16 KB: 35% (still poor)
  • 32 KB: 45% (limited help)
  • 64 KB: 55% (some relief)
  • 128 KB: 70% (better but insufficient)

Test Case 3: Adaptive Bitrate Streaming (ABR)

Workload: Codec switches between 1080p ↔ 4K based on network conditions

Buffer Size Variation: 1 MB (1080p) to 2.5 MB (4K)

Challenge: Working set size changes dynamically

Expected Hit Rates:

  • 16 KB: 85% (handles both resolutions)
  • 32 KB: 92% (overhead for lower bitrate)
  • 64 KB: 96% (excellent for all modes)

Test Case 4: Worst Case (Rapid Resolution Changes)

Workload: Frequently switch 360p ↔ 1080p ↔ 4K (stress test)

Misses Due To: Working set thrashing, codec state invalidation

Expected Hit Rates:

  • 8 KB: 60% (high miss penalty)
  • 32 KB: 80% (partial buffering)
  • 64 KB: 88% (most stable)

📈 Performance & Optimization Metrics

Metric Definition Formula Target
Cache Hit Rate (%) % of memory accesses satisfied by cache Hits / Total Accesses > 95% (video)
Average Access Time (AAT) Expected time per memory access Hit Time + Miss Rate × Miss Penalty < 5 cycles
Frame Buffering Stalls % of frames delayed due to cache misses Miss Events > 6000 cycles / Frame < 2%
Performance/Area Ratio Hit rate per unit die area Hit Rate / Cache Area (mm²) > 5.0
Energy Efficiency Energy per memory access Power × AAT < 20 nJ/access
Throughput (streams/W) Number of streams per watt Concurrent Streams / Power > 3.0
ROI (Diminishing Returns) Performance gain per mm² added Δ Hit Rate / Δ Area Track knee point

🎯 Key Learning Objectives

  • Understand cache size impact on hit rate (diminishing returns curve)
  • Analyze capacity misses vs. conflict misses
  • Calculate average access time (AAT) across cache sizes
  • Recognize working set size and its relationship to cache sizing
  • Evaluate tradeoffs: performance vs. area vs. power
  • Identify optimal cache size for specific workloads (sweet spot)
  • Understand scalability with multiple concurrent streams
  • Estimate frame buffering and quality impact from cache misses
  • Apply cost-benefit analysis to cache design decisions
  • Predict performance when workload exceeds cache capacity
