📋 Project Overview

In this project, you'll analyze CPU performance using Cycles Per Instruction (CPI) as the primary metric. You'll examine how instruction types (ALU, memory, branch), pipeline hazards, branch prediction, and cache behavior affect overall performance. The goal is to understand performance bottlenecks, calculate CPI for different workloads, and identify optimization opportunities in modern CPUs.

🎯 Real-World Scenario

TechCorp Data Processing: Multi-Task CPU Scheduler

Background: TechCorp operates a high-performance computing cluster with 1,000 nodes, each with dual Intel Xeon processors (3.5 GHz, 6-core). The cluster processes mixed workloads: scientific simulations (matrix math), database queries (memory-intensive), and web servers (branchy code). The OS scheduler multiplexes 48 concurrent tasks on 12 cores (4 tasks per core, time-sliced). Performance targets: execute 100+ billion instructions/second per socket, maintain <50 ms latency for interactive queries, and optimize energy (mW/GIPS). The bottleneck: CPI varies from 0.8 (math-heavy) to 4.0 (branchy code), causing unpredictable latency and wasted CPU power.

Performance Requirements:

  • CPU Frequency: 3.5 GHz (3.5 × 10⁹ cycles/second)
  • Pipeline Depth: 14 stages (Haswell-like)
  • Issue Width: 4 instructions/cycle (quad-issue superscalar)
  • Target CPI: ≤ 1.0 (ideally close to 0.8 for superscalar)
  • Throughput: ≥ 3.5 billion instructions/second (IPC ≥ 1.0)
  • L1 Cache Hit Rate: ≥ 95% (latency ~4 cycles)
  • L2 Cache Hit Rate: ≥ 90% (latency ~10 cycles)
  • Branch Prediction Accuracy: ≥ 95% (misprediction penalty ~20 cycles)
  • Task Latency Tail (P99): < 50 ms
  • Power Efficiency: < 5 mW/GIPS

⚙️ CPU Performance Fundamentals

What is CPI?

Definition: Cycles Per Instruction (CPI) is the average number of clock cycles required to execute one instruction.

CPI Basics: Perfect execution: CPI = 1.0 (one instruction per cycle) Superscalar (4-issue): CPI = 0.25 (four instructions per cycle) Realistic (hazards): CPI = 1.5-2.0 (stalls from dependencies) Memory-bound: CPI = 4.0+ (waiting for L2/L3 cache) Inverse: IPC (Instructions Per Cycle) = 1 / CPI Example: Task: 1 billion instructions @ CPI 1.5 Time = 1,000,000,000 instr × 1.5 cycles/instr ÷ 3.5 GHz = 1.5 × 10⁹ cycles ÷ 3.5 × 10⁹ cycles/sec = 0.429 seconds

The CPI Equation

CPI = (Base CPI) + (Stalls from hazards) + (Stalls from memory) = 1.0 + (RAW stalls) + (Branch misprediction stalls) + (Cache miss stalls) Base CPI ≈ 1.0 (one instruction per cycle with no stalls) For N-issue superscalar: Base CPI ≈ 1/N (but hard to achieve) RAW (Read-After-Write) Hazards: Dependent instructions must wait for result Example: load r1, [r0]; add r2, r1, r3 → 1-2 cycle stall Branch Misprediction: Wrong path fetched/executed, must flush pipeline Penalty: ~20 cycles (pipeline depth) per misprediction Frequency: (1 - branch_accuracy) / branch_rate Cache Misses: L1 miss → L2 hit: +6 cycles (L2 latency - L1 latency = 10-4) L2 miss → L3 hit: +30-50 cycles L3 miss → Memory: +150-300 cycles (DRAM latency) Example calculation: Base CPI: 1.0 RAW hazards (4% of instr): 0.04 × 2 = 0.08 Branch penalties (1% mispredict rate × 20 cycles): Branches are ~15% of code Mispredicts = 1% × 15% = 0.15% instr Penalty = 0.0015 × 20 = 0.03 L1 cache miss penalty (5% miss rate × 6 cycles): L1 reads = ~30% of instr Misses = 5% × 30% = 1.5% Penalty = 0.015 × 6 = 0.09 Total CPI = 1.0 + 0.08 + 0.03 + 0.09 = 1.20

Instruction Classification

By Execution Latency

Instruction Type Latency (cycles) Throughput (per cycle) Frequency in Code
Integer ALU (ADD, SUB, XOR, etc.) 1 4 (quad-issue) ~40%
Integer Multiply (IMUL, MULH) 3-4 1 (single-issue) ~5%
Integer Divide (IDIV, MOD) 20-40 1 (single-issue) ~1%
Float ADD/SUB 3-4 2 (dual-issue) ~10%
Float Multiply (FMA) 4-5 2 ~8%
Float Divide (FDIV) 10-20 1 (single-issue) ~1%
Load (L1 hit) 4 2 (dual-issue) ~20%
Load (L1 miss, L2 hit) 10 2 ~1%
Store (L1 hit) 1 (commit) 2 (dual-issue) ~10%
Branch (predicted correct) 0 (no delay) 1 ~3%
Branch (mispredicted) 20 (flush penalty) 0.5 ~0.15%

By Data Dependencies (Hazards)

RAW (Read-After-Write): Instruction must wait for prior instruction's result

Example sequence (Xeon-like with 3-cycle FMA latency): FMA r1, r2, r3, r4 (multiply-add, latency 4) [Cycle 1-4] ADD r5, r1, r6 (needs r1, RAW hazard) [Cycle 5-8: waits 4 cycles] CPI impact: First instr 1.0 + Second instr 4.0 = 2.5 average

By Memory Behavior

Memory-Bound vs Compute-Bound:

  • Compute-Bound: Bottleneck is ALU throughput (CPI ~0.8-1.2)
  • Memory-Bound: Bottleneck is cache misses (CPI ~2.0-4.0+)

📊 Multi-Task Workloads

Workload 1: Sequential Integer Math

Code Profile: Tight loops of integer arithmetic (no branches, predictable memory)

Instruction Mix: 50% ALU, 20% Multiply, 15% Load (L1 hit), 10% Store, 5% Branch (correct)

Cache Behavior: 98% L1 hit rate (working set ~8 KB)

Branch Prediction: 99% accuracy (simple loops)

Expected CPI:

  • Base: 1.0
  • ALU (50% × 1 cycle): 0.5
  • Multiply (20% × 3 cycles - 1): 0.4
  • Load (15% × 4 cycles - 1): 0.45
  • Store (10% × 0): 0
  • Branch misprediction (1% × 0.05 × 20): 0.01
  • Total: ~0.8 CPI (excellent!)

Workload 2: Matrix Multiplication (GEMM)

Code Profile: Triple nested loop (3D array traversal), heavy FMA usage

Instruction Mix: 5% ALU (loop control), 40% FMA, 30% Load, 10% Store, 15% Branch

Cache Behavior: 85% L1 hit, 10% L2 hit, 5% L3 miss (working set >1 MB on large matrices)

Branch Prediction: 98% (outer loop branches predictable, inner less so)

Expected CPI:

  • Base: 1.0
  • FMA (40% × 4 cycles - 1): 1.2
  • L1 Load (25.5% × 4 - 1): 0.76
  • L2 Load (3% × 10 - 1): 0.27
  • L3 Miss (1.5% × 100 - 1): 1.5
  • Branch misprediction (2% × 0.15 × 20): 0.06
  • Total: ~1.9 CPI (compute-limited on small matrices, memory-limited on large)

Workload 3: Database Query (Pointer Chasing)

Code Profile: Hash table/B-tree traversal (unpredictable memory access, branches)

Instruction Mix: 30% ALU, 40% Load (random address), 15% Store, 10% Branch, 5% Multiply

Cache Behavior: 70% L1 hit, 15% L2 hit, 15% L3 miss (pointer-chasing inherent misses)

Branch Prediction: 85% (branchy code, hard to predict)

Expected CPI:

  • Base: 1.0
  • ALU (30% × 1): 0.3
  • L1 Load (28% × 4 - 1): 0.84
  • L2 Load (6% × 10 - 1): 0.54
  • L3 Miss (6% × 100 - 1): 5.94 (MEMORY STALL!)
  • Branch misprediction (15% × 0.15 × 20): 0.45
  • Total: ~3.6 CPI (severely memory-bound)

Workload 4: Web Server (Branchy Code)

Code Profile: Protocol parsing, string matching, conditional logic

Instruction Mix: 40% ALU, 25% Load, 20% Branch, 10% Store, 5% Multiply

Cache Behavior: 92% L1 hit (instruction cache miss > data cache miss), 8% L2 hit

Branch Prediction: 92% (many data-dependent branches)

Expected CPI:

  • Base: 1.0
  • ALU (40% × 1): 0.4
  • Load (25% × 4 - 1): 0.75
  • Branch misprediction (8% × 0.20 × 20): 0.32
  • Total: ~1.5 CPI (branch misprediction is significant)

Workload 5: Image Processing (SIMD)

Code Profile: Vectorized operations (4-8 elements per instruction), linear access patterns

Instruction Mix: 10% ALU, 50% SIMD (FMA/Add), 25% Load, 10% Store, 5% Branch

Cache Behavior: 96% L1 hit (sequential memory), 4% L2 hit

Branch Prediction: 98% (simple outer loop)

Expected CPI:

  • Base: 1.0
  • SIMD FMA (50% but 4 elements/instr = 200% work): 0.5 / 4 = 0.125
  • Load (25% / 4 elements): 0.06
  • Total: ~0.4 IPC (but measured in elements: ~1.6 elements/cycle) or ~2.5 CPI per microinstruction

Workload 6: Mixed Workload (TechCorp Cluster)

Code Profile: 40% math (Workload 1), 30% GEMM (Workload 2), 20% database queries (Workload 3), 10% web (Workload 4)

Expected CPI: 0.4 × 0.8 + 0.3 × 1.9 + 0.2 × 3.6 + 0.1 × 1.5 = 0.32 + 0.57 + 0.72 + 0.15 = 1.76 CPI

Throughput: 3.5 GHz / 1.76 CPI = 2.0 billion instructions/second (57% of peak)

Analysis: The database queries (20% of time, 3.6 CPI) and GEMM (30% of time, 1.9 CPI) are the bottlenecks

📈 Performance & Optimization Metrics

Metric Definition Formula Target
CPI (Cycles Per Instruction) Average cycles needed per instruction Total cycles / Total instructions < 1.2 (good)
IPC (Instructions Per Cycle) Average instructions executed per cycle 1 / CPI or Total instructions / Total cycles > 0.8 (good)
Instruction Throughput (GIPS) Billion instructions per second CPU frequency GHz / CPI > 2.8 GIPS (70% of 3.5 GHz)
Execution Time Wall clock time to complete task Total instructions × CPI / Frequency < 0.5 seconds for 1B instr
L1 Cache Hit Rate (%) % of L1 accesses that hit (L1 hits / Total L1 accesses) × 100 > 95%
L2 Cache Hit Rate (%) % of L2 accesses that hit (L2 hits / Total L2 accesses) × 100 > 80%
Branch Prediction Accuracy (%) % of branches predicted correctly (Correct predictions / Total branches) × 100 > 95%
RAW Stalls (% of cycles) % of time waiting for data dependencies (RAW stall cycles / Total cycles) × 100 < 5%
Memory Stall Rate (%) % of time waiting for memory (Memory stall cycles / Total cycles) × 100 < 20%
Power Efficiency (mW/GIPS) Watts per billion instructions/sec Power (mW) / Throughput (GIPS) < 5 mW/GIPS
