📋 Project Overview

In this project, you'll analyze how CPU registers and memory change during a file data encryption operation. You'll track register values, memory modifications, and the efficiency of data movement through the memory hierarchy.

🎯 Real-World Scenario

CloudVault Security: Encrypting Client Files

Background: CloudVault operates a cloud storage service with 50,000+ daily file uploads. To meet GDPR compliance, all files must be encrypted using AES-256 before storage. The encryption pipeline processes 512-byte file chunks on a custom CPU architecture.

Key Operations:

  • Key Expansion: Load encryption key into R0-R3
  • Data Loading: Load 16-byte plaintext block into memory addresses 0x1000-0x100F
  • SubBytes: Modify plaintext bytes via register transformations
  • ShiftRows: Reorder bytes using memory writes
  • MixColumns: XOR operations across registers R4-R7
  • AddRoundKey: Store ciphertext to output memory (0x2000-0x200F)

⚙️ Complexity Factors

Register Hazards:

Hazard Type Impact Stall Cycles
Read-After-Write (RAW) R0 read before previous write completes 2 cycles
Write-After-Read (WAR) Write to R0 before previous read completes 1 cycle
Write-After-Write (WAW) Consecutive writes to same register 0 cycles (resolved)

Memory Access Patterns:

  • Cache Hit Rate: Sequential reads from 0x1000-0x100F = 100% L1 hit
  • Cache Miss Penalty: Non-sequential jumps to 0x2000 = 50-cycle penalty
  • Memory Bandwidth: AES requires 16 reads + 16 writes = 32 memory transactions
  • Load-to-Use Latency: Memory load takes 3 cycles, affects dependent instructions

Instruction-Level Parallelism:

  • ILP Opportunity: 2-4 independent instructions execute in parallel
  • Dependency Chain: Some SubBytes operations depend on key expansion (critical path)
  • Pipelining Efficiency: 70% of instructions overlap in 5-stage pipeline

📊 Test Cases

Test Case 1: All Zeros (Best Case)

Input: Plaintext block = 0x00 0x00 ... 0x00

Expected Outcome: Zero register hazards, 100% cache hit rate, minimal memory contention

Key Metric: Cycles Per Block (CPB) < 50

Test Case 2: High Register Pressure (Worst Case)

Input: Plaintext block with alternating patterns forcing all 8 registers to be in use

Expected Outcome: Multiple RAW hazards, memory stalls, register spilling

Key Metric: CPB > 100, register utilization = 100%

Test Case 3: Real File Data

Input: ASCII text: "CloudVault_Security_Protocol_V2_"

Expected Outcome: Realistic register/memory pressure mix

Key Metric: CPB ≈ 70-80

Test Case 4: Random Data

Input: Random byte sequence (entropy analysis)

Expected Outcome: Uniform distribution across hazard types

Key Metric: CPB ≈ 75, hazard rate = 45%

📈 Performance Metrics & Targets

Metric Definition Target
Cycles Per Block (CPB) Total CPU cycles to encrypt one 16-byte block < 70
Register Hazard Rate % of instructions affected by RAW/WAR/WAW < 40%
Memory Stall Cycles Cycles spent waiting for memory operations < 20
Register Utilization % of 8 registers in active use 60-80%
ILP Factor Avg instructions executing per cycle > 2.0
Throughput (MB/s) File encryption speed > 500 MB/s @ 3GHz

  • Understand trade-offs between register pressure and memory bandwidth

  • Apply performance optimization techniques to real-world workloads
