Step-by-step instructions for designing, verifying, and optimizing digital logic circuits

🚀 Quick Start (5 Steps)

1

Open the Simulator

Launch Project4_4Bit_ALU_Simulator.html in your web browser. You'll see:

  • Control panel with A input, B input, and OpCode selection
  • Binary representation of all inputs
  • 4-bit output with flags (Carry, Overflow, Zero)
  • Component execution details (gate count, propagation delay, power)
  • Execution trace log with step-by-step operation details
  • Verification table showing timing and area metrics
2

Set Input Values

Configure test inputs:

Input A (0-15): First 4-bit operand
Input B (0-15): Second 4-bit operand
OpCode (3-bit): Selects which ALU operation to perform
OpCode Values:
000 = ADD | 001 = SUB | 010 = AND | 011 = OR
100 = XOR | 101 = NOT | 110 = SHL | 111 = SHR
3

Execute the ALU

Click "Execute ALU ▶️" to run the operation. The simulator will:

  • Route inputs through selected ALU components (Adder, Logic Unit, Shifter)
  • Calculate the result based on the OpCode
  • Set output flags (Carry, Overflow, Zero)
  • Display component details: gate count, latency, power
  • Log execution steps to trace log
4

Analyze Results

Review the output:

  • Result (4-bit): ALU output in binary and decimal
  • Carry Flag (C): Set if addition overflows (> 15)
  • Overflow Flag (V): Set if signed arithmetic overflows
  • Zero Flag (Z): Set if result is 0
  • Timing: Propagation delay should be < 5ns for real-time constraint
  • Area: Gate count should be < 200 for cost constraint
5

Verify Against Test Cases

Run through the 16 provided test vectors to ensure:

  • All arithmetic operations (ADD, SUB) produce correct results
  • All logic operations (AND, OR, XOR, NOT) work correctly
  • Shift operations (SHL, SHR) move bits correctly
  • Flags (Carry, Overflow, Zero) are set correctly
  • Timing meets < 5ns requirement
  • Area is within < 200 gate budget

📊 Understanding the Display Panels

Inputs & Binary Section

Shows: Input values in both decimal and 4-bit binary format
Color coding: Each bit displays as green (0) or red (1) for visual clarity
Example (A=5):
Input A: Decimal 5
Binary: 0110 (0101 in 4-bit)

Output & Flags Section

Shows: ALU result in 4-bit binary and decimal, plus status flags
Flags explained:
  • C (Carry): Arithmetic carry-out or borrow (for ADD/SUB)
  • V (Overflow): Signed overflow detection (rarely used in this 4-bit design)
  • Z (Zero): Result is zero (useful for conditional jumps)
Example (5 + 12 = 17, overflow):
Result: 0001 (1)
C=1 (Carry Out) ← Overflow detected!
V=0 (No Signed Overflow)
Z=0 (Not Zero)
The 4-bit result is 0001 (1) because 17 mod 16 = 1. The Carry flag tells us we overflowed.

Components displayed:
  • Gate Count: Number of logic gates required
  • Propagation Delay: Time from input to output (ns)

  • Arithmetic/Logic Unit details (for debugging)
  • Multiplexer output selection

🔍 Common Test Cases to Run

Basic Arithmetic (A=5, B=3)

OpCode 000 (ADD): 5 + 3 = 8 ✓
OpCode 001 (SUB): 5 - 3 = 2 ✓
Expected: Both pass, no carry

Logic Operations (A=10=1010, B=5=0101)

OpCode 010 (AND): 1010 & 0101 = 0000 (0) ✓
OpCode 011 (OR): 1010 | 0101 = 1111 (15) ✓
OpCode 100 (XOR): 1010 ^ 0101 = 1111 (15) ✓
OpCode 101 (NOT): ~1010 = 0101 (5) ✓

Edge Cases (Overflow)

A=15, B=1, OpCode 000 (ADD):
15 + 1 = 16 → Result: 0000 (0), C=1 (Carry) ✓

A=0, B=5, OpCode 001 (SUB):
0 - 5 = -5 → Result: 1011 (11 in 2's comp), C=1 (Borrow) ✓

Shift Operations

A=3 (0011), OpCode 110 (SHL):
Shift Left: 0011 << 1 = 0110 (6), C=0 ✓

A=12 (1100), OpCode 111 (SHR):
Shift Right: 1100 >> 1 = 0110 (6), C=0 ✓

📝 Design Optimization Tips

If Timing is Too Slow (> 5ns)

Problem: ADD/SUB take 6ns with ripple carry adder
Solution 1 - Carry Lookahead Adder (CLA):
  • Reduces delay to ~3ns
  • Adds ~20 extra gates
  • Trade: speed vs. area

Solution 2 - Pipelining:
  • Split into 2-stage pipeline
  • Each stage: ~3ns
  • Trade: latency vs. throughput

If Area is Too Large (> 200 gates)

Problem: Current design uses 36+4+4+8+4 = 56 gates per operation
Solution 1 - Gate Sharing:
  • Reuse AND gates for NOT operation
  • Combine adder with subtractor logic

Solution 2 - Reduced Op Set:
  • Remove rarely-used operations
  • Implement SUB via ADD + NOT (borrow NOT gate)

If Power is Too High (> 50mW)

Problem: DIV unit and large gate counts consume power
Solution 1 - Clock Gating:
  • Disable unused ALU units when not in use
  • Save 40% power on average workload

Solution 2 - Lower Voltage:
  • 2.5V instead of 3.3V → 57% power reduction
  • Cost: slightly slower performance

✅ Verification Checklist

  • ☐ All 16 test vectors pass with correct results
  • ☐ Carry flag sets on overflow (ADD only)
  • ☐ Zero flag sets when result = 0
  • ☐ Bitwise operations (AND/OR/XOR/NOT) work correctly
  • ☐ Shift operations (SHL/SHR) preserve bits correctly
  • ☐ Subtraction uses 2's complement correctly
  • ☐ Propagation delay < 5ns (timing requirement)
  • ☐ Gate count < 200 (area requirement)
  • ☐ Power dissipation < 50mW (thermal requirement)
  • ☐ No timing violations in critical path
