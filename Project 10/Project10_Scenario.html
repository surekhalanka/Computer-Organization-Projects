Scenario: Network Switch Routing Architecture

📋 Project Overview

In this project, you'll design and optimize multiplexer networks in high-speed packet switches. You'll analyze how data selection logic routes packets from multiple input ports to output ports, measure latency and throughput, and optimize for minimal conflicts and maximum bandwidth utilization. The goal is to understand multiplexers as the backbone of switching fabric and their performance bottlenecks.

🎯 Real-World Scenario

NetFlow Corp: Data Center Network Switch Design

Background: NetFlow operates a tier-1 data center with 100+ racks, each with 40+ servers. A core 32-port network switch routes traffic between servers, storage, and external networks at 400 Gbps aggregate throughput. The switch uses a crossbar switching fabric with 32 input ports × 32 output ports, each port handling 12.5 Gbps (400 Gbps ÷ 32 ports). Multiplexer arrays select which packet from 32 input queues goes to which output port. With 48-byte headers + 1500-byte payloads (≈1.5 KB packets), the switch must process 300,000 packets/second and maintain <1 microsecond latency (per-hop). Switching delay is dominated by mux selection time (~10 nanoseconds for 32:1 mux) and queue contention.

Performance Requirements:

  • Input Ports: 32 ports, each 12.5 Gbps (400 Gbps total)
  • Output Ports: 32 ports (non-blocking crossbar—any input to any output)
  • Mux Array: 32 × 32 crossbar = 1,024 multiplexers (one per input-output pair)
  • Packet Rate: 300,000 packets/sec (aggregate, avg 1.5 KB)
  • Mux Selection Latency: < 10 nanoseconds (combinational)
  • Switch Latency (per-hop): < 1 microsecond (queue delay + mux delay)
  • Throughput: 400 Gbps (non-blocking, no packet loss under 100% offered load)
  • Fairness: No starvation (all ports get fair bandwidth)
  • Power Budget: Mux fabric < 50W (data center constraint)

⚙️ Multiplexer Architecture

What is a Multiplexer?

Definition: Combinational logic that selects one of N inputs based on ⌈log₂(N)⌉ control signal bits.

2:1 Mux (Simplest): Inputs: A, B Select: S (0 or 1) Output: Y = (S ? B : A) Truth table: S | Y 0 | A 1 | B 4:1 Mux: Inputs: I0, I1, I2, I3 Select: S1, S0 (2 bits, selects one of 4) Output: Y = (S? I[S1:S0]) S1 S0 | Y 0 0 | I0 0 1 | I1 1 0 | I2 1 1 | I3 32:1 Mux (Network Switch): Inputs: 32 input ports Select: S (5 bits: 2^5 = 32 options) Output: Packet from selected input port

Mux Implementation (Datapath & Control)

Datapath (Data Selection)

Function: Route packet bits from selected input to output

  • Width: 64 bits (8 bytes per cycle @ 12.5 Gbps)
  • Latency: 2-3 gate delays (~200 ps at 65nm tech)
  • Area: ~1,000 transistors (2:1 mux) × log₂(N) stages

Control Path (Mux Select Logic)

Function: Decode routing decision, generate select signals

  • Input: Packet header (destination IP/MAC)
  • Lookup: Routing table (CAM or TCAM, 10-20 ns latency)
  • Output: Select signal S[4:0] (selects output port)
  • Latency: Routing table lookup (10-20 ns) + mux delay (1-2 ns) = 11-22 ns total

Crossbar Switching Fabric

Input Ports (0-31): Port 0 ──┐ Port 1 ──┼─→ [Mux Array 32×32] ──→ Output Ports (0-31) Port 2 ──┼─→ [Each (i,j) mux] ──→ Port j ... │ selects from input i Port 31 ──┘ Complete Crossbar: - Mux(0,0): Select output 0 from input 0 if needed - Mux(0,1): Select output 1 from input 0 if needed - ... - Mux(31,31): Select output 31 from input 31 Total: 32 × 32 = 1,024 multiplexers Each mux: 32:1 selection → 5 control bits Total control: 32 × 5 = 160 control bits per cycle

Data Selection Strategies

Strategy 1: Fixed Routing

Decision: Route packet to output based on destination address (lookup table)

Input packet: [Dest IP: 192.168.1.100] ↓ Lookup table: 192.168.1.* → Output port 5 ↓ Mux select: S = 5 (route to port 5)

Pros: Simple (no adaptation), predictable

Cons: No load balancing; hot spots create congestion

Mux Pressure: All packets to same destination → one output port saturates

Strategy 2: Adaptive Load-Balanced Routing

Decision: Route packet to least-loaded output port (among valid paths)

Input packet: [Dest: any path to 192.168.1.0/24] ↓ Valid outputs: Ports 5, 6, 7 (all reach destination) ↓ Load measurement: Port 5 queue = 500 bytes, Port 6 = 100 bytes, Port 7 = 300 bytes ↓ Min load Select: S = 6 (least congested output)

Pros: Balances load, reduces tail latency

Cons: Complex lookup (need multiple routing table entries)

Mux Pressure: Distributed—packets spread across multiple outputs

Strategy 3: Hash-Based Routing (Consistent)

Decision: Hash packet 5-tuple (source IP, dest IP, source port, dest port, protocol) to output

Input packet: [10.0.0.1:12345 → 192.168.1.100:80, TCP] ↓ Hash 5-tuple: Hash(flow) mod 32 = 7 ↓ Mux select: S = 7 (deterministic for this flow)

Pros: Fast (just hash), preserves packet order within flow

Cons: Uneven distribution if hash is poor

Mux Pressure: Depends on hash quality; can cause hotspots

Strategy 4: Multicast (Fan-Out)

Decision: Route packet to multiple output ports (e.g., broadcast)

Input packet: [Broadcast to all 32 ports] ↓ Mux select: Enable 32 outputs simultaneously ↓ Replicate: Create 32 copies in fabric

Pros: Supports group communication

Cons: High mux complexity (need fan-out logic)

Mux Pressure: One input drives all 32 outputs (peak traffic)

📊 Data Selection & Routing Workloads

Test Case 1: Uniform Random Routing

Workload: Each incoming packet randomly selects one of 32 outputs

Packet Distribution: Poisson arrival (λ = 300k packets/sec), uniform output selection

Mux Load: Each output port receives 1/32 of traffic (balanced)

Queue Contention: Minimal (output queues distribute evenly)

Expected Results:

  • Mux Utilization: 100% (all muxes active selecting from inputs)
  • Output Load Balance: 1/32 per port (perfect)
  • Switch Latency: ~2 microseconds (queue wait + mux delay)
  • Packet Loss: ~0% (no congestion)
  • Throughput: 400 Gbps (100% utilization)

Test Case 2: Fixed Routing (Hot Spot)

Workload: 80% of traffic destined to single output port (port 0), 20% to others

Packet Distribution: Deterministic routing by destination

Mux Load: Port 0 muxes heavily loaded, port 1-31 muxes lightly loaded

Queue Contention: Port 0 output queue saturates (320 Gbps vs 12.5 Gbps capacity)

Expected Results:

  • Mux Utilization: 80% port 0 muxes, 6% ports 1-31 (imbalanced)
  • Output Load Balance: Port 0 = 320 Gbps (oversubscribed!), ports 1-31 = 2.5 Gbps avg
  • Switch Latency: > 10 microseconds (port 0 queue grows unbounded)
  • Packet Loss: ~75% dropped at port 0 (exceeds 12.5 Gbps capacity)
  • Effective Throughput: Only ~50 Gbps to port 0, rest drops

Test Case 3: Load-Balanced Routing (Adaptive)

Workload: Same traffic as Test 2 (80/20 split), but switch uses adaptive routing

Routing Decision: Route 80% traffic to 8 different output ports (load balance)

Mux Load: Distributed across 8 output ports, each carrying 40 Gbps

Queue Contention: Spread across 8 ports (40 Gbps / 12.5 Gbps = 3.2× oversubscription per port)

Expected Results:

  • Mux Utilization: ~25% of all muxes (8 output ports active)
  • Output Load Balance: 8 ports × 40 Gbps + 24 ports × 5 Gbps (better spread)
  • Switch Latency: ~5 microseconds (still congested, but better than case 2)
  • Packet Loss: ~60% (still oversubscribed, but improved)
  • Effective Throughput: ~160 Gbps (40% improvement over fixed routing)

Test Case 4: Hash-Based Routing (Flow Consistent)

Workload: 1,000 flows, each flow with consistent 5-tuple (deterministic routing)

Packet Distribution: 100 packets per flow (0.1 MB per flow, total 100 MB)

Flow-to-Port Mapping: Hash(5-tuple) mod 32 = output port (same for all packets in flow)

Hash Distribution: Ideally uniform (each port gets ~31 flows)

Expected Results:

  • Mux Utilization: 100% (all flows active)
  • Output Load Balance: ~31 flows per port (balanced if hash is good)
  • Switch Latency: ~2 microseconds (uniform traffic)
  • Packet Loss: ~0% (no hot spots)
  • Throughput: 400 Gbps (100% utilization)
  • Flow Order Preservation: 100% (packets from same flow never reordered)

Test Case 5: Multicast (Broadcast)

Workload: 10% of packets are broadcast (replicate to all 32 outputs), 90% unicast

Fan-Out Factor: 10% × 32 ports = 3.2 effective destinations per packet

Mux Load: Broadcast packets activate all 32 output muxes simultaneously

Queue Contention: Broadcast packets compete with unicast for output bandwidth

Expected Results:

  • Mux Utilization: ~115% (some outputs overloaded by broadcasts)
  • Output Collision Rate: ~10% (broadcasts collision with unicast)
  • Switch Latency: ~3 microseconds (added contention)
  • Packet Loss: ~5% (broadcasts drop due to output queue overflow)
  • Effective Throughput: ~380 Gbps (20 Gbps lost to collisions)
  • Replication Overhead: 10% × 31 extra copies = 3.1% bandwidth overhead

Test Case 6: Hierarchical Routing (Multi-Stage Switch)

Workload: Packets routed through 3-stage mux tree (32:32 fabric decomposed)

Architecture: Stage 1 (input stage muxes) → Intermediate crossbar → Stage 3 (output stage muxes)

Mux Count: 32 input muxes + 1,024 core crossbar + 32 output muxes = 1,088 total

Latency Cascade: Delay = Stage1 + Core + Stage3 (additive)

Expected Results:

  • Mux Utilization: Similar to single-stage (~100%)
  • Switch Latency: 3× higher (~6 ns per stage × 3 = 18 ns vs 10 ns single-stage)
  • Throughput: ~380 Gbps (congestion in multi-stage fabric)
  • Blocking Probability: ~5% (some connections blocked if intermediate stages congested)

📈 Performance & Design Metrics

Metric Definition Formula Target
Mux Utilization (%) % of muxes making active selections (Active Packets / Total Packets) × 100 > 90%
Output Port Utilization (%) % of output capacity used per port (Traffic per port / Port capacity) × 100 ~97% (high, but < 100%)
Load Balance Ratio Ratio of max to avg output load Max load per output / Avg load < 1.2 (balanced)
Switch Latency (μs) Time from input to output Routing lookup + Queue wait + Mux delay < 1 μs
Packet Loss (%) % of packets dropped (queue full) (Dropped / Offered) × 100 < 0.1% (near-lossless)
Throughput (Gbps) Data rate delivered to outputs Sum of output port traffic ≥ 400 Gbps (non-blocking)
Mux Array Power (W) Power consumed by all muxes Dynamic + Leakage (1,024 muxes) < 50 W
Fabric Blocking Probability (%) % of connections blocked (multi-stage) (Blocked Requests / Requests) × 100 < 1% (very low)
Fairness (Jain Index) Measure of equal bandwidth allocation (Sum L_i)² / (32 × Sum L_i²) > 0.95 (fair)
