Understanding the Output

📊 Hit Rate (%)

Definition: Percentage of memory accesses satisfied by the cache (no main memory access required)

Formula: (Cache Hits / Total Accesses) × 100%

Example: 900 hits out of 1000 accesses = 90% hit rate

Why it matters: Higher hit rate = fewer expensive main memory accesses = faster performance

Target: > 90% for web workloads

⏱️ Average Access Time (AAT)

Definition: Expected time per memory access, including cache hits and misses

Formula: AAT = Hit Time + (Miss Rate × Miss Penalty)

Example calculation (90% hit rate, direct-mapped):

AAT = 1 cycle + (0.10 × 100 cycles) AAT = 1 + 10 = 11 cycles per access

Why it matters: Lower AAT = faster memory system = better overall CPU performance

Target: < 10 cycles for good performance

📈 Total Cycles

Definition: Total CPU cycles consumed by all memory accesses in the simulation

Formula: Total = (Hits × Hit Time) + (Misses × Miss Penalty)

Example (900 hits, 100 misses):

Total = (900 × 1) + (100 × 100) Total = 900 + 10,000 = 10,900 cycles

Why it matters: Lower total cycles = faster program execution

Interpreting Architecture Differences

📌 Example Run: Temporal Locality Workload (80% hot pages)

Configuration: 32 KB cache, 64-byte lines, 1000 accesses

Architecture Hit Rate AAT Total Cycles Why?
Direct-Mapped 80% 21 cy 21,000 cy Conflict misses: hot pages map to same line
2-Way Set-Assoc 90% 11 cy 11,000 cy 2 choices reduce conflicts
4-Way Set-Assoc 93% 8 cy 8,000 cy 4 choices further improve hit rate
Fully-Associative 95% 7 cy 7,500 cy No conflicts, but slower hit time (2 cy vs 1 cy)

Key Insight: 4-way achieves 93% hit rate (near optimal) with much lower area/power than fully-associative → best for web servers!

🔬 Key Concepts Explained

Cache Misses: Capacity vs. Conflict

Capacity Misses

Occur when the working set exceeds cache size. Cannot be fixed by changing associativity.

Example: Accessing 10 MB of data with a 8 MB cache → 20% capacity misses guaranteed

Conflict Misses

Occur when multiple addresses map to same cache location. Increased associativity reduces these.

Example (direct-mapped): Addresses 0x0000 and 0x8000 both map to same line → thrashing

Solution: 2-way or 4-way associativity allows both to coexist

Least Recently Used (LRU) Replacement

Policy: When cache is full, evict the entry not used for longest time

Implementation: Maintain access timestamp or linked list per cache line

Why effective: Recent accesses often indicate temporal locality (likely to access again soon)

Alternative: FIFO (First In, First Out), Random, Optimal (not implementable)

Measuring Energy Efficiency

Energy Per Access (nJ/access)

Formula: Energy = Power × AAT

Example:

4-way cache: 3.2W × 8 cycles / 3GHz = 8.5 nJ per access Fully-assoc: 8.0W × 7 cycles / 3GHz = 18.7 nJ per access Verdict: 4-way is 2.2× more energy efficient!

Impact: Web servers running 24/7 → small power savings compound

🎯 Lab Experiments

Experiment 1: Effect of Cache Size

Objective: Measure how cache size affects hit rate

Procedure:

  • Fix: 4-way set-associative, 64-byte line, Temporal workload, 1000 accesses
  • Vary: Cache size from 8 KB to 64 KB
  • Record: Hit rate, AAT for each size

Expected Result: Hit rate increases, then plateaus (capacity limit reached)

Practical Implication: Diminishing returns beyond 32 KB for typical web workloads

Experiment 2: Workload Sensitivity

Objective: Compare how different architectures respond to workload changes

Procedure:

  • Fix: 32 KB cache, 64-byte line, 1000 accesses
  • Vary: Workload type (Uniform, Temporal, Spatial, Worst)
  • Record: Hit rate for Direct-Mapped vs 4-Way vs Fully-Associative

Expected Result: Fully-associative most robust; direct-mapped fails on worst case

Experiment 3: Associativity Trade-offs

Objective: Find optimal associativity balancing performance and cost

Procedure:

  • Compute: Performance/Area ratio for each architecture
  • Formula: (Hit Rate / Total Area in mm²)
  • Compare: Direct (1.0x area), 2-way (1.2x), 4-way (1.3x), FA (3.5x)

Expected Result: 4-way offers best performance/area ratio (5.8x vs 5.0x for FA)

⚠️ Common Issues & Troubleshooting

❌ "All architectures show same hit rate"

Cause: Workload has good spatial locality (sequential access) → no conflicts possible

Solution: Try "Worst Case" or "Uniform Random" workload to see differences

❌ "Direct-mapped shows very low hit rate"

Cause: Working with addresses that conflict → "Worst Case" workload trigger

Solution: This is expected! Direct-mapped is vulnerable to conflict misses. Try "Temporal" workload.

❌ "Fully-associative slower than 4-way despite higher hit rate"

Cause: FA hit time = 2-3 cycles vs 1 cycle for others

Lesson: AAT = Hit Time + Miss Penalty. Longer hit time can outweigh higher hit rate!

❌ "Metrics seem incorrect"

Check: Verify configuration settings before running

Solution: Click "Reset" button and reconfigure from defaults

📚 Extended Reading

  • Cache Performance Metrics: AAT = H + M(MP), where H=hit time, M=miss rate, MP=miss penalty
  • Amdahl's Law: Overall speedup limited by cache-bound portion of workload
  • Working Set Theory: Subset of memory pages actively used; cache size should match working set
  • Prefetching: Hardware or software can hide miss latency by fetching before miss occurs
  • Cache Coherence: Multi-core systems need protocols (MESI) to maintain consistency
  • Inclusive vs. Exclusive: L1 contained in L2 (inclusive) or separate (exclusive)?
