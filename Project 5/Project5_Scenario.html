Scenario: Web Server Cache Optimization

📋 Project Overview

In this project, you'll compare different CPU cache architectures (Direct Mapped, Fully Associative, and Set-Associative) and evaluate their performance on web server workloads. You'll analyze cache hit rates, miss penalties, and power consumption across different cache designs to optimize for a production web server handling millions of requests.

🎯 Real-World Scenario

FastWeb Corp: Optimizing Web Server Performance

Background: FastWeb operates a global web server infrastructure serving 100 million page requests/day. Each request requires CPU cache lookups for frequently accessed data: user sessions, database indices, and content metadata. The choice of cache architecture impacts both performance (latency) and power consumption. FastWeb must select the optimal cache design for their next-generation server CPU.

Performance Constraints:

  • Page Load Time: Target < 200ms (cache hit critical)
  • Cache Latency: Hit latency < 5 cycles, Miss penalty < 100 cycles
  • Die Size: Cache area < 50mm² (cost constraint)
  • Power Budget: < 10W for L1 cache @ 3GHz
  • Hit Rate Target: > 90% for typical web workloads
  • Working Set: 1000+ unique pages (16KB each) = 16MB+ data

⚙️ Cache Architecture Designs

Design 1: Direct-Mapped Cache

Structure: 1 cache line per memory address (block placement)
Formula: Cache Index = (Memory Address) MOD (Cache Size)
Hit Time: 1 cycle (fastest)
Area: Smallest (simple hardware)
Pros: Fast access, low power, minimal area
Cons: High miss rate due to conflict misses
Example (8-entry cache):
• Address 0x000 → Cache slot 0
• Address 0x008 → Cache slot 0 (conflict! evicts address 0x000)
• Address 0x100 → Cache slot 0 (thrashing!)
Typical Hit Rate: 75-85% (web workloads)

Design 2: Fully Associative Cache

Structure: Any cache line can hold any memory address
Replacement: LRU (Least Recently Used) policy
Hit Time: 2-3 cycles (parallel tag comparison)
Area: Largest (complex hardware: tag comparators)
Pros: Lowest miss rate, no conflict misses
Cons: Expensive, high power, large die area
Example (8-entry cache):
• Address 0x000 → Any free slot (perfect flexibility)
• Address 0x008 → Any free slot (no conflicts)
• Address 0x100 → Any free slot (still no conflicts)
Typical Hit Rate: 92-97% (best for web workloads)

Design 3: Set-Associative Cache (Recommended)

Structure: S ways × N sets = Cache Size
Formula: Set Index = (Memory Address) MOD (Num Sets)
Associativity: 2-way, 4-way, 8-way common
Hit Time: 1-2 cycles (parallel comparison within set)
Area: Moderate (S tag comparators per set)
Pros: Good balance of speed, area, hit rate
Cons: Some conflict misses possible
Example (8-entry, 2-way set-associative):
• 4 sets × 2 ways
• Address 0x000 → Set 0, Way 0 or Way 1 (can hold either)
• Address 0x008 → Set 0, Way 0 or Way 1 (shares set, not conflict)
• Address 0x004 → Set 2, Way 0 or Way 1 (different set)
Typical Hit Rate: 88-93% (good balance)

📊 Web Server Workload Test Cases

Test Case 1: Uniform Random Access (Baseline)

Workload: 1000 random memory addresses accessed uniformly

Expected Hit Rate: Direct 78%, 2-way 88%, 4-way 92%, Full 95%

Key Insight: Tests cache management without locality

Test Case 2: Temporal Locality (Hot Pages)

Workload: 80% of references to 20% of pages (frequent access to popular pages)

Expected Hit Rate: Direct 82%, 2-way 92%, 4-way 94%, Full 96%

Key Insight: Real web workload—popular content accessed repeatedly

Test Case 3: Spatial Locality (Sequential)

Workload: Sequential access to memory blocks (typical for database scans)

Expected Hit Rate: Direct 95%, 2-way 96%, 4-way 97%, Full 98%

Key Insight: Prefetch friendly—cache line reuse optimal

Test Case 4: Worst Case (Conflict Misses)

Workload: Addresses that map to same cache lines (0, 32KB, 64KB, ...)

Expected Hit Rate: Direct 12%, 2-way 85%, 4-way 91%, Full 95%

Key Insight: Direct-mapped thrashes; associativity solves it
