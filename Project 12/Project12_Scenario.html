📋 Project Overview

In this project, you'll analyze Direct Memory Access (DMA), a critical component for high-performance I/O systems. DMA allows peripherals (disks, network, GPU) to transfer data directly to/from main memory WITHOUT CPU intervention, freeing the CPU for other tasks. You'll model disk I/O latencies, DMA transfer times, interrupt handling, and overall system throughput to understand modern I/O subsystems in servers and data centers.

🎯 Real-World Scenario

StorageFlow Inc: High-Performance Database Server

Background: StorageFlow Inc operates a fleet of database servers handling 100,000 concurrent database queries from financial trading firms. Each server runs a 2-socket Intel Xeon system with 256 GB RAM, dual 10 Gbps network NICs, and NVMe SSD storage (1 TB, ~500K IOPS, <1 ms latency). The system must achieve:

Performance Requirements:

  • Disk I/O Throughput: ≥ 10 GB/s (saturate 2× 10 Gbps NICs)
  • DMA Transfer Latency: < 100 μs (microseconds)
  • Query Latency (P99): < 50 ms (end-to-end)
  • CPU Utilization: < 30% for I/O overhead (rest for queries)
  • Interrupt Overhead: < 5% of total CPU cycles
  • Memory Bandwidth: ≥ 80 GB/s sustained (3× typical disk read rate)
  • DMA Efficiency: ≥ 95% (minimize idle time, maximize throughput)
  • Power Efficiency: < 2 mW per 100 MB/s transferred

Challenge: Previous design used PIO (Programmed I/O) where CPU copies data byte-by-byte → 80% CPU utilization! Switching to DMA can free 50%+ of CPU cycles for actual queries.

⚙️ DMA Fundamentals

1. Programmed I/O (PIO) vs Direct Memory Access (DMA)

PIO: CPU Does All Work

Disk Read with PIO (Programmed I/O): Step 1: CPU sends "read sector 12345" command to disk controller Step 2: CPU polls/waits for data ready (inefficient polling or interrupt) Step 3: Disk transfers data to controller buffer (fast, ~1 MB/s from disk firmware) Step 4: CPU reads data word-by-word from disk controller: for (i = 0; i < 4096; i++) memory[base + i] = disk_controller_data_port; [STALLS CPU FOR ~4096 READ CYCLES!] Step 5: Repeat for next disk block Problem: CPU BLOCKED during all data transfer! - Disk → Controller: ~5-100 us (disk latency) - Controller → Memory: ~1-10 ms (4 KB block at slow PIO) - CPU utilization: 95%+ for I/O, no query processing!

DMA: Let Hardware Do It

Disk Read with DMA (Direct Memory Access): Step 1: CPU sends "read sector 12345 via DMA to 0x80000000" to DMA controller Step 2: CPU returns to query processing (NOT BLOCKED!) Step 3: DMA controller manages transfer: - Sends read command to disk - Waits for disk ready - Transfers disk → controller buffer - Transfers controller buffer → memory (direct!) - Increments memory address pointer - Decrements byte count Step 4: DMA completes, sends INTERRUPT to CPU Step 5: CPU interrupt handler: - Receives DMA completion interrupt - Marks buffer ready for processing - Returns to query (total CPU time: ~1-5 microseconds) Benefit: - CPU FREE during DMA transfer (~1-10 ms)! - CPU utilization for I/O: <5% - 95% CPU available for queries!

Why DMA is Essential

  • CPU-Memory speed gap: Modern CPUs ~3 GHz (can read/write 12-50 GB/s), disks ~500 MB/s. CPU is 1000× faster!
  • PIO blocks CPU: Transferring 1 MB with PIO on modern CPU takes ~200 cycles (57 ns/byte × 1M), CPU can't do anything else
  • DMA offloads: DMA controller manages transfer in hardware, CPU processes queries in parallel
  • Interrupt-driven: Only interrupt CPU when transfer complete (~1 μs), not for every byte!

DMA Transfer Process (Step-by-Step)

Step Action Time CPU Blocked?
1. Command CPU writes DMA descriptor (source, dest, count) ~1 μs No
2. Queue DMA controller queues transfer request ~0.1 μs No
3. Disk Access Send read to disk, wait for data ready ~100-500 μs (SSD), ~5-10 ms (HDD) No (CPU free!)
4. Transfer DMA copies disk buffer → memory via interconnect ~10-100 μs (4 KB @ 100 GB/s) No (hardware path)
5. Interrupt DMA sends interrupt to CPU (completion signal) ~1-5 μs Brief (ISR only)
6. ISR (Interrupt Service Routine) CPU handles interrupt, mark buffer ready ~1-2 μs Yes (brief)
Total (CPU overhead) Sum of CPU activities ~3-8 μs ~3-8 μs out of 100+ μs

Example: 1 GB Read from SSD

With PIO: Bytes: 1,000,000,000 CPU cycles per byte: 10-20 cycles (read, write, loop overhead) CPU cycles total: 10,000,000,000 cycles @ 3.5 GHz: 10B / 3.5B = 2.86 seconds (CPU 100% blocked!) With DMA: Transfer: 1 GB / 100 GB/s = 10 ms (DMA hardware, CPU free!) CPU overhead: 10 ms / (4 KB blocks) × 3 μs/interrupt = 7.5 ms Total CPU overhead: ~10 ms (1% CPU utilization for I/O!) Speedup: 2.86 s (PIO) → 10 ms (DMA) = 286× faster! (CPU freed for queries)

3. Interrupt Handling & Overhead

Interrupt Service Routine (ISR) Latency

Phase Time (μs) Description
Hardware interrupt delay ~0.1-0.5 Time for DMA to signal interrupt to CPU
CPU pipeline flush ~0.5-1.0 CPU stops current instruction, drains pipeline
Context save (registers) ~0.5-1.0 Push IP, flags, registers to stack
ISR dispatch ~0.1-0.2 Jump to interrupt handler
ISR execution ~0.5-1.0 Mark buffer, queue callbacks
Context restore ~0.5-1.0 Pop registers, return to interrupted task
Total ISR latency ~3-5 Sum of all phases

Interrupt Coalescing (Optimization)

Problem: If disk sends 10,000 interrupts/sec (10 Gbps ÷ 4 KB blocks), CPU spends 10ms/sec just in ISRs!

Solution: Coalesce multiple completions into single interrupt

Without coalescing: 10,000 interrupts/sec × 3 μs/interrupt = 30 ms CPU/sec (3%) With coalescing (10 blocks/interrupt): 1,000 interrupts/sec × 4 μs/interrupt = 4 ms CPU/sec (0.4%) Trade-off: Latency vs throughput - No coalesce: Lower latency (fast completion), high CPU overhead - Coalesce 100: Higher throughput, slightly higher latency (microseconds)

4. DMA Channels & Queuing

Multi-Channel DMA

Request Queuing & Scheduling

Queue Type Capacity Scheduling Fairness
FIFO (First-In-First-Out) 16-64 entries In-order Simple, but slow device blocks fast device
Priority Queue 64 entries (8 priority levels) High priority first Low priority may starve
Fair Queuing 64 entries (8 channels) Round-robin across channels Each channel gets 1/8 bandwidth
Weighted Queuing 64 entries (8 channels, weights) Weighted round-robin High-priority channels get more bandwidth

📊 Workload Scenarios

Workload 1: Sequential Disk Read (SSD)

Pattern: Read 10 GB from SSD sequentially (database table scan)

I/O Characteristics:

  • Block size: 4 KB
  • Number of blocks: 2.5 million
  • Disk latency: 100 μs (SSD seek/read)
  • Disk throughput: 500 MB/s
  • Transfer time: 20 seconds

DMA Efficiency: ~95% (few stalls, sequential access)

Workload 2: Random Disk Reads (HDD)

Pattern: 10,000 random 4 KB reads from HDD (random access query)

I/O Characteristics:

  • Block size: 4 KB
  • Number of blocks: 10,000
  • Disk latency: 8 ms (HDD seek + rotational)
  • Disk throughput: 100 MB/s
  • Total time: 10,000 × 8 ms = 80 seconds (if serial!)

DMA Efficiency: ~30% (high latency variance, bottleneck is disk seeks, not transfer)

Workload 3: Network I/O (10 Gbps NIC)

Pattern: Receive 100 Mbps sustained network traffic (distributed database replication)

I/O Characteristics:

  • Packet size: 1500 bytes (jumbo frame)
  • Packets/second: 100 Mbps / 1500 bytes = 8,333 packets/sec
  • Interrupt rate: 8,333 / sec
  • CPU overhead: 8,333 × 4 μs = 33 ms CPU/sec (3.3%)
  • NIC throughput: 100 Mbps = 12.5 MB/s

DMA Efficiency: ~90% (high interrupt coalescing helps)

Workload 4: Mixed I/O (Disk + Network)

Pattern: Disk reads (50 GB/s) + Network writes (10 Gbps simultaneous)

I/O Characteristics:

  • Disk read: 500 MB/s (4 KB blocks every 8 μs)
  • Network write: 1.25 GB/s (outgoing traffic)
  • Memory bandwidth needed: 500 + 1250 = 1750 MB/s
  • Available: 100 GB/s (plenty of headroom!)
  • Interrupt rate: ~500 MB/s / 4 KB = 125,000 int/sec (with coalescing: 12,500)
  • CPU overhead: 12,500 × 4 μs = 50 ms CPU/sec (5%)

DMA Efficiency: ~92% (good scheduling, no memory bottleneck)

Workload 5: Burst I/O (Database Checkpoint)

Pattern: Write 100 GB to disk as fast as possible (database checkpoint/backup)

I/O Characteristics:

  • Block size: 64 KB (larger blocks for sequential write)
  • Number of blocks: 1.6 million
  • Disk throughput: 1 GB/s (SSD NVMe)
  • Total time: 100 seconds
  • Interrupt rate: 1 GB/s / 64 KB = 15,625 interrupts/sec (uncoa leced)
  • With coalescing (10 blocks): 1,562 interrupts/sec × 4 μs = 6.2 ms CPU/sec (0.6%)

DMA Efficiency: ~99% (large blocks, high throughput, efficient)

Workload 6: Interactive Query Mix (Realistic)

Pattern: Mixture of all above: 20% sequential read, 30% random read, 25% network, 15% disk write, 10% checkpoints

Expected Metrics:

  • Effective I/O throughput: ~150 MB/s (blended)
  • Average interrupt rate: ~8,000 /sec
  • CPU overhead: ~4% (with coalescing)
  • DMA efficiency: ~90% (realistic, accounting for stalls)
  • Query latency: ~50 ms (P99, dominated by disk seek time)
